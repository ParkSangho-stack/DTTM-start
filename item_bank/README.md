# DTTM 주간 설문 문항은행과 버전관리

> 이 폴더의 문항은 모두 **개발 중인 예비문항**입니다. 검증된 척도가 아닙니다.

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `item_bank.csv` | 문항은행 원본. 모든 후보·보류·폐기 문항이 여기 있습니다. 수정안은 이 파일에서만 관리합니다. |
| `render.py` | 문항은행을 검사하고 문항 설계표(마크다운)를 출력합니다. `python3 item_bank/render.py --check` |
| `releases/` | 실제 조사에 쓰는 **조사판(form)**. 한 번 배포한 조사판 파일은 고치지 않습니다. 아직 배포한 조사판은 없습니다. |
| `CHANGELOG.md` | 문항은행 버전별 변경 기록(추가·수정·삭제·유지와 근거). |

## 2. 두 층 구조: 문항은행과 조사판

- **문항은행(bank)**: 매주 검토 결과를 반영하는 곳입니다. 버전은 `bank v0.1`, `v0.2`처럼 올립니다. 문항은행이 바뀌어도 진행 중인 조사에는 영향이 없습니다.
- **조사판(form)**: 특정 조사 차수에 실제로 배포한 문항 묶음입니다. 이름은 `F{순번}-{대상}-{bank 버전}` 형식입니다(예: `F1-S-v0.3` = 첫 조사판, 대학생판, bank v0.3에서 동결). 배포 시점에 `releases/`에 사본을 만들고 git 태그(`form-F1-v0.3`)를 붙입니다.
- 한 패널(예: 0주~12주)이 진행되는 동안 그 패널의 조사판은 **고정**합니다. 문항은행에서 바뀐 내용은 다음 패널(또는 미리 정한 적용 시점)부터 적용합니다.

## 3. 문항 ID와 개정 규칙

- ID 형식: `{국면}-{구분}{번호}`. 구분은 `C` 공통, `U` 대학생 맥락, `W` 직장인 맥락, `H` 보류입니다. 사건·비용 문항은 `E1-`, `CM-`, `CT-`, `IA-`를 씁니다.
- **ID는 다시 쓰지 않습니다.** 폐기된 ID에 새 문항을 넣지 않습니다.
- 수정 수준에 따라 다르게 처리합니다.

| 수정 수준 | 예 | 처리 | 이전 자료와의 비교 |
|---|---|---|---|
| 표기 수정 | 띄어쓰기, 맞춤표 | 같은 ID, 같은 `rev` | 그대로 비교 |
| 경미한 문구 수정 | 어순, 예시 단어 교체 | 같은 ID, `rev` +1 | 연결 검증 후 비교(아래 4장) |
| 의미 변경 | 측정 개념·국면·회상기간·척도 변경 | **새 ID** 부여, 이전 ID는 `retired` | 직접 비교하지 않음 |

- `status` 값: `candidate`(후보, 아직 배포 전) → `active`(현재 조사판에 포함) → `retired`(폐기). `hold`(보류)는 근거가 쌓일 때까지 조사판에 넣지 않는 문항입니다.

## 4. 문항 변경의 적용 시점과 비교 가능성

1. **적용 시점**
   - 기본: 다음 패널의 0주(기준조사)부터 적용합니다.
   - 패널 중간에는 바꾸지 않습니다. 다만 윤리 문제나 응답자 대다수가 문항을 잘못 이해한 것이 확인되면 그 문항을 **중단**(삭제)만 하고, 대체 문항은 넣지 않습니다. 중단 전 자료는 `flag_suspended`로 표시해 보관합니다.
2. **기준문항(anchor) 유지**: 한 번의 개정에서 국면별 공통문항 5개 중 **3개 이상은 그대로** 둡니다. 이 기준문항으로 버전 간 척도를 연결합니다.
3. **연결 검증(bridging)**: `rev`가 바뀐 문항은 새 패널 0주에 응답자를 무작위로 반분해 이전 문구와 새 문구를 각각 받습니다(분할 설문). 두 문구 간 부하량·절편 동일성(또는 IRT DIF)을 확인해 차이가 없으면 같은 문항으로 이어서 분석합니다.
4. **분석 규칙**: 버전이 섞인 자료를 합쳐 분석할 때는 모든 버전에 공통인 문항만으로 점수를 만들거나, 기준문항을 고정한 동시 보정(concurrent calibration)을 씁니다. 버전 변수(`form_id`, `item_rev`)는 모든 응답 행에 기록합니다.

## 5. 변경 결정 규칙

- 새 근거(문헌, 전문가 평정, 인지면접, 실제 응답자료)가 없으면 문항은 **유지**입니다.
- 근거가 있으면 먼저 `추가 후보`·`수정 후보`·`삭제 후보`로만 표시합니다. 후보는 연구자가 승인해야 문항은행에 반영됩니다.
- 실제 응답자료가 없을 때는 응답 분포·신뢰도·요인구조에 관한 판단을 하지 않습니다.
